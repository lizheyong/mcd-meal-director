# 四个人，一张真实核价的餐单

**这是构造的四人需求 + 真实的官方 MCP 业务调用。** 2026-10-14 北京时间 17:22—17:24，使用麦当劳上海徐家汇餐厅（天钥桥路 1 号）当前到店菜单。只做配餐与核价，没有创建订单。

## 用户需求

> 四个人，总预算 120 元。小林不吃辣，小周不要含糖饮料，小陈想吃鸡肉，小许想和大家分享小食。每人一个汉堡和一杯饮料，再安排共享小食。大家同意基础餐费四人平摊，个人升级加价由本人承担。使用上海徐家汇的公共门店做演示。

## 第一版：100.30 元

购物清单只有三条套餐明细，分餐时拆给四人：

| 向门店购买 | 组成与归属 | 接口核价 |
| --- | --- | ---: |
| 堡堡随心拼（7 件任选）× 1 | 巨无霸给小林，板烧鸡腿堡给小陈；可乐中杯各 1；麦乐鸡 5 块 × 2 和中薯条 × 1 四人分享 | 72.50 元 |
| 人气经典随心配 × 1 | 高达吉士双牛堡 + 无糖可口可乐中杯，给小周 | 13.90 元 |
| 精选超值随心配 × 1 | 麦香鸡 + 可乐中杯，给小许 | 13.90 元 |
| **整单** | **4 个汉堡、4 杯饮料、10 块麦乐鸡和 1 份中薯条** | **100.30 元** |

四人均摊的精确值是 25.075 元。以分为单位分配，小林与小周各承担一分尾差。共享麦乐鸡可分为 3 / 2 / 3 / 2 块，中薯条四人分享。

| 成员 | 专属餐品 | 麦乐鸡份数 | 建议分摊 |
| --- | --- | ---: | ---: |
| 小林 | 巨无霸 + 可乐中杯 | 3 块 | 25.08 元 |
| 小周 | 高达吉士双牛堡 + 无糖可口可乐中杯 | 2 块 | 25.08 元 |
| 小陈 | 板烧鸡腿堡 + 可乐中杯 | 3 块 | 25.07 元 |
| 小许 | 麦香鸡 + 可乐中杯 | 2 块 | 25.07 元 |
| **合计** | | **10 块** | **100.30 元** |

配餐满足案例中的人数、主要口味要求和 120 元总预算，余下 19.70 元。本案例没有比较所有可能组合，因此不声称最低价。均摊是案例中四人事先约定的规则。

## 临时改餐：只动一个人，整单重新核价

> 小周想把牛肉堡换成麦香鱼，无糖可乐保留，其他人的先别动。加价由小周承担。

依据套餐详情，将小周所在组合第一轮的餐品编码由 `521316` 换为 `1600`。把完整三条购物明细重新提交给 `calculate-price`，官方返回总价 **101.30 元**：

| 成员 | 变化 | 改餐后分摊 |
| --- | --- | ---: |
| 小林 | 餐品和共享关系保持不变 | 25.08 元 |
| 小周 | 高达吉士双牛堡 → 麦香鱼；无糖可乐保留；承担加价 1.00 元 | 26.08 元 |
| 小陈 | 餐品和共享关系保持不变 | 25.07 元 |
| 小许 | 餐品和共享关系保持不变 | 25.07 元 |
| **合计** | **整单增加 1.00 元，仍在预算内** | **101.30 元** |

这里体现了 Skill 的工作：保留具体成员与餐品的对应关系、把共享套餐计入购物清单一次、按真实选项改餐、重新核算整单，并解释差价归谁。

## 复现

配置好 `MCD_MCP_TOKEN` 并安装依赖后运行：

```sh
npm run mcp -- call calculate-price examples/quote-before.input.json
npm run mcp -- call calculate-price examples/quote-after.input.json
```

复现调用会查询当前价格，可能因为时段、菜单、门店供应或账户权益变化而不同。若接口提示商品不可售，重新调用门店菜单和餐品详情，根据新的实际选项构造清单。
